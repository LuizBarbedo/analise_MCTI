PROJETO - NOME: 320400163-Desenvolvimento de sistema de gestão fabril que contemple rastreabilidade de processo e qualidade, cálculo dos indicadores de OEE, gestão de movimentação de materiais.
DESCRIÇÂO: O projeto consiste em desenvolver um sistema de gerenciamento fabril que contemple as ações de administração de pessoal, planejamento, sequenciamento, realização de operações, chamada e consumo de materiais de acordo com operações e configurações pré-determinadas integrado com ERP fornecendo dados para consulta e apontamentos diversos ao longo da linha produtiva. Isso se dará com o desenvolvimento de interfaces e configurações / integração de várias funcionalidades do sistema com o ERP existente além de sistema para registro de ensaios e genealogia do produto. Ele também deverá auxiliar o gestor na tomada de decisão como direcionamento de pessoas nos postos de trabalho, acompanhamento da produção de forma online, gestão de parada, consumo de materiais (estoque), problemas de manutenção e não-qualidade, acionamento de pessoas em caso de problemas produtivos, redução de papel impresso (ordem de produção) onde todas essas características serão registradas e poderão ser consultadas num momento futuro em caso de necessidade.
Realizado benchmarking de ferramentas de mercado que atendessem o objetivo buscado com esse projeto porém com a particularidade dos processos fabris existentes é necessário desenvolver várias telas para configurações conforme mapeamento realizado. É necessário desenvolver integrações entre sistemas e links diversos para que o usuário final (operador) tenha uma interface única e amigável para entrada de informações.
O projeto está subdividido em 3 partes: OEE (máquina e mão-de-obra/célula), movimentação de material e módulo de qualidade. Cada uma das partes se desdobra em vários outros entregáveis de acordo com os requisitos do projeto.
Aquisição de hardware para instalação do sistema e simulação do desenvolvimento validando a aplicabilidade de todas as funções executadas.
Um dos itens mais impactantes do projeto, além de toda interface e configurações do sistema, é a mudança de mindset dos operadores para que informem além da entrada no momento certo da operação para contabilização dos tempos e cálculos dos indicadores o motivo correto das paradas (de execução da produção por uma parada não planejada) para direcionamento dos trabalhos de melhoria futuros. Isso exige disciplina, atenção não só do operador mas como das pessoas envolvidas pois não é automatizado como um sinal de máquina. Além disso, toda a especificação e parametrização de inputs e outputs do processo requer um trabalho minucioso de mapeamento de atividades executadas em todos os locais contemplados nesse projeto.

¹) Nos sistemas supervisórios de mercado só é possível monitorar postos com sinais de máquina, porém temos muitos postos manuais, devendo o sistema ter postos máquina e bancada integrados, ou seja, quando um operador com determinado turno estiver operando numa máquina, o status dele fica como “operando em máquina”. Caso não tivesse essa integração, ficaria como parada não justificada para futuramente alguém fazer manutenção dos dados e questionar as atividades realizadas. Assim como quando o colaborador estiver de férias, foi feita integração com sistema do RH para que não haja intervenção manual, o sistema ‘bloqueia’ o usuário daquele operador.
²) No sistema contratado, o qual foi customizado, o operador consegue abrir ordem/operação, consultar a respectiva documentação e realizar o apontamento da quantidade fabricada tudo numa só tela. Anteriormente à discussão e desenvolvimento, haviam mais telas onde o operador precisaria imputar informações, onerando o tempo do mesmo.

Desta forma, solicitamos ao MCTI reconsideração deste projeto, bem como os valores envolvidos, reconhecendo o enquadramento como atividade de PD&I.

Os projetos de P&D buscam apresentar resultados para superar um determinado problema ou dificuldade. O esforço realizado para superá-lo constitui a atividade de P&D, que, como resultado, apresentará uma solução, ou não, para o problema dado. Essa atividade sempre apresentará um resultado, mesmo que seja um apontamento de que a premissa adotada e testada para superação da barreira ou problema não deve ser mais seguida, pois não funciona. Assim, é necessário descrever com clareza a barreira ou o desafio tecnológico que é o objeto da atividade, para caracterizar adequadamente um projeto como de P&D.
